# Details

- 用户指出路径选择器不应沿用危险确认弹窗的 Cancel 优先语义：默认焦点必须是 Select。
- [路径选择器设计](../../checklist/path-picker.md)及[对话框焦点约定](../../checklist/tui-interaction-components.md#焦点与键盘)已明确此例外，不改其他弹窗。
- 原实现将路径解析/有效性验证和子目录列举绑在一次加载里；加载期间 Select 不可聚焦，Cancel 取得焦点，回车会取消。
- 用户进一步指出：进入列表子目录时已有上一操作确认其存在。首次打开仍可能取自过期的持久化 cwd 或 `~`，因此选择时保留独立校验与规范化，但不等待子目录列举。
- 范围限于 path-picker 的本地状态机、渲染、测试及本设计记录；Select 从打开起可聚焦/按下，确认异步验证成功才返回绝对目录，无效路径不返回；Cancel、筛选及导航保持原行为。
- 不改变冻结 RPC contract，也不触碰并行的 Native 崩溃调查文件。
- 验收：先以受控 Loading 状态重现原来回车误触 Cancel；修复后 JVM/Linux x64 Native 的 path-picker ViewModel 与渲染测试均通过。新增测试覆盖加载中默认焦点、列目录未完成时确认、目录被删除后拒绝、迟到确认不选择旧目录。设置视图及应用视图 JVM 回归通过。当前未重新链接 CLI，也未修改用户试用的本地二进制。
